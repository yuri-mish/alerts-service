# alerts-service

Щодня бере з alerts.in.ua історію тривог за ~30 днів по регіонах з таблиці `regions` і актуалізує Postgres.
Тривоги ріжуться на відрізки за київською добою (отже й за місяцем) -> `alert_periods`. Повна перебудова: `npm run rebuild`.

- Рівень (жовтий/червоний): зберігається лише останній відомий, зміни рівня не відстежуються.
- У звіти (`/periods`, `/summary`, `/1c/alerts`) йдуть лише повітряні тривоги (`air_raid`); артобстріли тощо лишаються тільки в `alerts`.
- Регіони: усі області, крім Луганської (16), Криму (29) і Севастополя (30).
- Тривога без кінця понад 3 доби (72 год) закривається як початок + 30 хв (`closed_by = stale_30min`); справжній кінець з API потім замінює це.
- API віддає лише ~30 днів: якщо сервіс простоїть довше, у даних буде дірка (warning у `sync_runs`).

## HTTP (https://alerts.starsam.net, заголовок `X-Api-Key`)

Ключі:
- **адміністратора** (env `API_KEY`): усі ендпоінти;
- **клієнтські** (таблиця `api_keys`, видає адмін): лише читання — `GET /periods`, `/summary`, `/1c/alerts`, `/alerts/{id}`;
  інше → 403. Ліміт `RATE_LIMIT_PER_MIN` (за замовчуванням 6) запитів на хвилину на ключ, понад → 429 + `Retry-After`.
  Невідомий або вимкнений ключ → 401; після 5 неправильних ключів з одного IP — 429 до кінця годинного вікна.
- CORS відкрито для будь-якого сайту (`Access-Control-Allow-Origin: *`), ключ передається в заголовку.

| Метод | Шлях | |
|---|---|---|
| GET | `/` | без ключа; лендінг з описом API і прикладами (`src/site/landing.html`) |
| POST | `/key-requests` | без ключа; заявка на ключ з лендінгу `{"name","company","purpose","email"}` → таблиця `key_requests` + Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` у `.env`); 3 заявки з IP на годину |
| POST | `/contact` | без ключа; «Написати автору» з лендінгу `{"name","contact","message"}` → Telegram (у таблиці `contact_messages` лишаються лише ті, що не вдалося надіслати); 5 повідомлень з IP на годину |
| POST | `/telegram/webhook` | вебхук бота (секрет у `X-Telegram-Bot-Api-Secret-Token`): кнопки «Прийняти» (створює ключ, адміну — готовий лист з ключем) / «Відмовити» (готовий лист з відмовою) |
| GET | `/stats` | без ключа; агрегат для графіка на лендінгу: години тривог за 30 днів по регіонах (кеш 10 хв) |
| GET | `/health` | без ключа; останній прогін |
| GET | `/keys` | адмін: список клієнтських ключів (без самих ключів) |
| POST | `/keys` | адмін: `{"name": "..."}` - новий ключ (показується **один раз**); `{"name": "...", "key": "..."}` - додати наявний ключ (від 8 символів) |
| PUT | `/keys/{id}` | адмін: `{"enabled": false}` - вимкнути, `{"name": "..."}` - перейменувати |
| DELETE | `/keys/{id}` | адмін: видалити ключ назавжди |
| GET | `/key-requests` | адмін: заявки на ключ (спершу ті, що чекають) |
| POST | `/key-requests/{id}/approve`, `/reject` | адмін: рішення по заявці → `{status, key, letter}` (ключ показується один раз) |
| GET | `/admin` | міні-адмінка (сторінка без ключа; дані — з ключем адміністратора) |
| POST | `/sync` | запустити оновлення (202 + runId); `?wait=1` - дочекатися результату |
| GET | `/runs`, `/runs/{id}` | журнал прогонів |
| GET | `/regions` | регіони |
| PUT | `/regions/{uid}` | `{"title": "...", "enabled": true}` - додати/змінити |
| | | **Обов'язковий лише `month`** (інакше 400); без `region` і `location` - усі області; невідомий параметр рядка запиту - теж 400 |
| GET | `/periods?month=2026-11&region=14&location=94&level=red&format=csv` | відрізки; `region`, `location` приймають список через кому: `region=14,31` |
| GET | `/1c/alerts?month=2026-11&region=14,31[&location=75][&level=red][&format=csv]` | вигрузка для 1С: `ПериодМесяц, ДеньМесяца, КодТеритории, ТипСобытия ("Тревога"), НомерТревоги` (порядок у дні по території), `Начало, Конец` (київський час ISO; `Конец` null/порожній, поки триває); тривога розрізана по київських добах: один рядок на добу (шматок через опівніч: `Конец` = 00:00:00 наступної доби) |
| GET | `/summary?month=2026-11&region=31[&location=75,76][&by=location]` | кількість тривог і години (з об'єднанням перекриттів; активна тривога — до поточного моменту) по рівнях + `all` |
| GET | `/alerts/{id}` | тривога з відрізками по добах |

```bash
curl -H "X-Api-Key: $KEY" "https://alerts.starsam.net/summary?month=2026-11&region=31"
curl -H "X-Api-Key: $KEY" -X POST "https://alerts.starsam.net/sync?wait=1"
```

## Розгортання (VPS, ~/projects/alerts)

- `.env.db` - `DATABASE_URL` (Postgres 18 на хості), `.env` - `ALERTS_TOKEN`, `API_KEY`, `PORT=6020`, `SYNC_TIME=03:30`, необов'язково `TIME_ZONE` (IANA, за замовчуванням `Europe/Kyiv`): за нею рахуються доби, місяці, `SYNC_TIME` і час у відповідях.
- `docker compose up -d --build` - контейнер у host-мережі, слухає `127.0.0.1:6020`, nginx -> https.
- Міграції застосовуються при старті. Разовий прогін: `docker compose run --rm alerts node src/sync-once.ts`.
- Тести (потрібен Postgres, працюють в окремій схемі): `set -a; . ./.env.db; set +a; npm test`.
